# Log

Curated history; release notes live in GitHub Releases.

## 2026-08-11 — Documentation Standard adoption

The repo adopts the Krateo Documentation Standard: the invariant docs bundle
(`docs/{index,overview,usage,configuration,api,examples,release,log}.md` + `docs/llms.txt`),
a runnable `examples/aws-s3-bucket`, a rewritten `README.md` with the six standard
sections, and the shared `lint-docs` check wired into `lint.yaml`. The pre-existing
prerequisite docs (`docs/authentication.md`, `docs/installing-controllers.md`) gain OKF
frontmatter (type `Runbook`).

## Catalog generation

The blueprints are generated by `tools/ackgen` from the upstream ACK CRD schemas — 242
single-resource blueprints across 68 AWS services, plus a set of composite stacks under
`blueprints/_stacks/`. The `aws-s3-bucket` blueprint is the reference the generator was
built and validated against; its quickstart provisions a real S3 bucket end to end.

Two design decisions worth keeping:

- **ACK, consumed directly.** ACK controllers already are Kubernetes controllers with
  their own CRDs and reconcilers, so Krateo consumes them via `CompositionDefinition`s.
  The KOG / oasgen (RestDefinition) pattern is intentionally not used here.
- **The schema is the contract.** `core-provider` derives the Composition CRD and portal
  form from `values.schema.json` only; `values.yaml` is a schema-valid example, not the
  source of truth. Defaults are scalar so CRD generation does not break.
