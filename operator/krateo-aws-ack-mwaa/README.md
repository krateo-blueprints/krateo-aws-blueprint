# ACK Mwaa controller — Krateo operator blueprint

> Generated by `tools/ackgen` from `tools/ackgen/ack-controllers.yaml`.

Wraps the upstream `mwaa-chart` chart (pinned **1.3.0**) so the controller for AWS
Mwaa installs the same way as everything else in Krateo: as a blueprint, not a
by-hand `helm install`.

Every `blueprints/mwaa/*` blueprint renders `mwaa.services.k8s.aws` custom
resources. Those resources do nothing until this controller is running.

## Install

```sh
helm install krateo-aws-ack-mwaa \
  oci://ghcr.io/krateo-blueprints/charts/krateo-aws-ack-mwaa \
  --namespace ack-system --create-namespace \
  --set ack.aws.region=eu-west-1
```

## Credentials

Prefer IRSA / EKS Pod Identity — no secret material enters the cluster:

```sh
--set ack.serviceAccount.annotations."eks\.amazonaws\.com/role-arn"=arn:aws:iam::<account>:role/<role>
```

A shared credentials file in a Secret also works:

```sh
--set ack.aws.credentials.secretName=aws-creds \
--set ack.aws.credentials.profile=default
```

## Values

Everything is forwarded under the `ack` key, which is the dependency alias. The alias is
what keeps this path identical across all the ACK wrappers in this catalogue — `ack.aws.region`
means the same thing for every service.

| Value | Default | Notes |
|---|---|---|
| `ack.aws.region` | `""` | Controller default region. Each blueprint's own `region` field overrides it per Composition via the `services.k8s.aws/region` annotation. Empty here **and** empty per-resource means no region at all, and resources never reconcile. |
| `ack.aws.endpoint_url` | `""` | FIPS / VPC endpoint / localstack. |
| `ack.aws.credentials.secretName` | `""` | Leave empty for IRSA. |
| `ack.serviceAccount.annotations` | `{}` | IRSA / Pod Identity role ARN. |
| `ack.installScope` | `cluster` | `namespace` restricts to `watchNamespace`. |
| `ack.deletionPolicy` | `delete` | **Destructive**: `delete` destroys the real AWS resource when the Kubernetes resource goes away. `retain` orphans it — still running, still billable. |
| `ack.log.level` | `info` | `debug`, `info`, `warn`, `error`. |

Any other upstream value passes through unchanged: the schema allows additional properties under
`ack`, so the table above is the curated surface rather than the limit.

## CRDs

No companion `-crds` chart, deliberately. The upstream chart ships its CRDs in its own `crds/`
directory, so `helm install` registers them with the controller. This matches `krateo-azure-aso`
(ASO installs its resource CRDs at runtime) and differs from `krateo-gcp-configconnector`, which
needs a `-crds` chart only because Config Connector's operator CRDs arrive as a plain YAML bundle.

## Verify

```sh
kubectl get pods -n ack-system
kubectl get crds | grep mwaa.services.k8s.aws
```

## Generated

This chart is generated by `tools/ackgen` from `tools/ackgen/ack-controllers.yaml`. To bump the
controller, change the version there and re-run:

```sh
cd tools/ackgen && go build -o ackgen . && ./ackgen -operators ack-controllers.yaml -out ../../operator
```

`tools/ackgen/operators_test.go` asserts every committed wrapper matches the pin file, so a
hand-edit fails CI.
